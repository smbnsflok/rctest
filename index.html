RingCentral Click-to-Dial Test

Click each link in order and note what happens. Screenshot the diagnostics and click log at the bottom when finished.

1 — Desktop app scheme (rcapp://)

Only works if the RingCentral desktop app is installed. A PWA cannot register this scheme.

1a · encoded plus
rcapp://r/dialer?number=%2B447700900123

Expected if desktop app present: RingCentral opens with the number in the dialer.

1b · no plus
rcapp://r/dialer?number=447700900123

Tests whether the leading + is required in the parameter.

1c · alternate path
rcapp://r/call?number=%2B447700900123

The dialer route may be r/call rather than r/dialer — unconfirmed, testing both.

2 — Telephone scheme (tel:)

Routes to the OS default telephony handler. RingCentral's PWA manifest does not declare a tel: protocol handler, so this will likely open FaceTime on macOS.

2a · tel with plus
tel:+447700900123

Note which application opens — that identifies the current OS default.

3 — Web / PWA links (https://)

The RingCentral PWA manifest declares no scope, so it defaults to the whole app.ringcentral.com origin. If the PWA is installed, links to that origin should open inside the PWA window rather than a browser tab.

3a · control — origin root
https://app.ringcentral.com/

This is the key test. Did it open in the standalone PWA window, or in a normal browser tab? That tells us whether PWA link capture works at all on this machine.

3b · candidate dialer deeplink — unverified
https://app.ringcentral.com/dialer?number=%2B447700900123

This URL format is a guess and is not from RingCentral's documentation. A 404 or a redirect to the main app is the expected failure — it does not invalidate test 3a.

Note on 3b: replace this URL once the documented deeplink format is confirmed. If no such URL exists, server-side RingOut via the REST API is the only client-agnostic route.
