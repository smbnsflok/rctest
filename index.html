RingCentral Dialer Deeplink Test

Route is fixed at /r/dialer. The only variable is how the phone number is encoded.

How to run: click each link in order. After each one, note whether the RingCentral app opened and whether the number landed in the dialer correctly. Return here with the back button between tests.

Test number is +44 7700 900123, inside Ofcom's reserved range for testing — it is not a live line.

Number format variants

A · E.164 digits, no plus — expected best
https://app.ringcentral.com/r/dialer?number=447700900123

Matches RingCentral's own documented example format (number=16501112222). Start here.

B · encoded plus (%2B)
https://app.ringcentral.com/r/dialer?number=%2B447700900123

The app receives a literal +447700900123. This is the correct way to send a plus in a query string.

C · raw plus — expected to fail
https://app.ringcentral.com/r/dialer?number=+447700900123

A raw + in a query string decodes to a space, so the app likely receives " 447700900123". Included to confirm this is the failure mode — if this one works, the app isn't using standard query parsing.

D · UK national format
https://app.ringcentral.com/r/dialer?number=07700900123

Tests whether the app normalises a local trunk-prefixed number rather than requiring E.164.

Control

E · dialer with no number
https://app.ringcentral.com/r/dialer

Proves the /r/dialer route itself resolves in the PWA. If this errors, the route is unsupported in the web app and no number format will help — that result matters more than A–D.
